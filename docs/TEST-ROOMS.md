# Перевірка оновлення: палати та ліжка

Це оновлення сервера і спільного React-інтерфейсу для Windows та Android. Перевстановлення APK саме для цих змін не потрібне.

## Оновлення існуючого сервера

1. Зробіть резервну копію штатним Backup-NoDocker.ps1. Не видаляйте PostgreSQL, `.env.nodocker`, `.local` або `.backups`.
2. Завершіть роботу старого сервера штатно (Ctrl+C у його вікні). Не запускайте другу копію: вона конфліктуватиме за порти 3000/443.
3. Оновіть файли з нового QureMed-Local-Server.zip у вашій існуючій папці сервера. Збережіть локальну конфігурацію, ключі та резервні копії.
4. Запустіть Update-QureMed.cmd від адміністратора, дочекайтесь успішної збірки. Запустіть сервер один раз через Start-QureMed-Without-Docker.cmd. Міграція 003 додає збереження історії видалених місць.
5. Перезапустіть клієнти. Обидва пристрої повинні підключатися до одного сервера. Адреса телефону — HTTPS-адреса комп'ютера (раніше 192.168.1.106), а не адреса роутера 192.168.1.1. Перевірте поточну IPv4 комп'ютера, якщо DHCP змінив адресу.

## Тест без реальних пацієнтів

| Дія | Очікуваний результат |
| --- | --- |
| Адміністратор створює палату «ТЕСТ» і ліжко «1» | На другому пристрої у відкритій вкладці запис з'являється після найближчого оновлення |
| Реєстратор відкриває палати | Бачить вільні місця, не бачить кнопок створення/видалення |
| Зареєструйте вигаданого тестового пацієнта на ліжко | Видалення зайнятого ліжка недоступне; сервер також відхиляє таку дію |
| Спробуйте видалити палату з ліжками | Кнопка недоступна: спочатку потрібно видалити всі її ліжка |
| Випишіть тестового пацієнта, видаліть вільне ліжко | З'являється підтвердження. Після підтвердження ліжко зникає |
| Відкрийте архівну картку тестового пацієнта | Стара палата та номер ліжка залишаються в госпіталізації |
| Видаліть порожню палату | Палата зникає; дія записана в журналі аудиту |
| Створіть палату з тим самим номером | Створюється новий запис; стара історія не переписується |

## Інтервал оновлення

Списки useData/useCareData перевіряються кожні **5 секунд**, доки вікно видиме. Доставка відповіді залежить також від мережі та сервера. Зміни на поточному пристрої викликають додаткове оновлення. Однакові одночасні GET-запити об'єднуються, щоб не накопичувати запити при повільному сервері. Фонові звукові сповіщення Android мають окремий інтервал; цією зміною він не змінюється.

Якщо другий пристрій не бачить змін: перевірте однакову адресу сервера, його роботу, Wi-Fi та помилки з'єднання. Це не автоматичне встановлення нових версій програми кожні 5 секунд — оновлюються дані.

Перевірено автоматично: збірка TypeScript/React та 30 серверних тестів. Роботу на фізичних пристроях перевірте за таблицею вище.
