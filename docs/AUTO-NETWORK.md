# Автоматична адреса сервера (Windows 2.5.2)

Під час установки та наступного запуску сервер визначає IPv4 активного фізичного Wi-Fi/Ethernet адаптера. Пріоритет має маршрут за замовчуванням з найменшою сумою метрик. VPN, WSL та віртуальні адаптери не обираються. Локальна мережа без інтернету підтримується. Якщо адаптерів декілька, обраний IP друкується у вікні сервера; потрібну адресу можна явно передати `scripts/Enable-LanHttps.ps1 -ServerIp <IPv4 цього ПК>` перед запуском. Звичайний запуск знову автоматично обирає основний адаптер.

При переході на інший Wi-Fi зупиніть сервер Ctrl+C і запустіть повторно. PUBLIC_URL, ALLOWED_ORIGINS і HTTPS-конфігурація оновляться. Дані PostgreSQL, паролі та сховище локального CA зберігаються. IP роутера не використовується як IP сервера. Якщо мережі немає, запуск видає пояснення, а не повертається до 192.168.1.106.

Телефон має бути в тій самій мережі. В налаштуваннях застосунку вкажіть нову адресу з рядка Phone. Автоматичного пошуку сервера телефоном ця зміна не додає. Для нової довіреної мережі Windows встановіть профіль Приватна: правило HTTPS діє тільки в цьому профілі. Перевірку сертифікатів не вимкнено. Якщо папку .local збережено, CA залишається тим самим.

Оновіть серверні файли в існуючій папці, зберігши .env.nodocker, .local та базу. Перевстановлення PostgreSQL не потрібне. Windows CI перевіряє вибір адреси на імітованих адаптерах; фактичне переключення Wi-Fi потрібно перевірити на ПК.
