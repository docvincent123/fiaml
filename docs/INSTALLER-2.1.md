# RehaFlow 2.1 — встановлення й робочі місця

GitHub Actions збирає RehaFlow-Windows-Installer (RehaFlow-Setup-x64.exe),
RehaFlow-Windows-x64 (портативний клієнт) і RehaFlow-Android-test-APK.
Інсталятор поки без комерційного підпису; APK підписаний тестовим ключем.

## Новий ПК

Запустіть EXE-інсталятор і виберіть один із режимів:

- **Робоче місце**: встановлює Windows-клієнт. Укажіть HTTPS-адресу вже наявного
  сервера та шлях до скопійованого з нього QureMed-Local-CA.crt. Довіру до
  сертифіката підтверджує користувач. База залишається на сервері.
- **Сервер центру**: встановлює клієнт та вихідні файли сервера в
  C:\ProgramData\QureMed\Server. Після завершення майстра оберіть установлення
  залежностей і запуск сервера. Для першого встановлення потрібен інтернет.
  Скрипт встановлює Node.js, PostgreSQL та Caddy за потреби, збирає React/API,
  пропонує фактичну IPv4-адресу ПК та налаштовує локальний HTTPS.
  PostgreSQL, що вже встановлений, потребує його чинного пароля.

Сервер працює, поки відкрите його вікно й ПК не засинає. Ярлик запуску сервера
у меню «Пуск» запускайте від адміністратора. Закриття клієнта не вимикає сервер.
WebView2 за відсутності встановлюється через кнопку у вікні клієнта.
Видалення програми не видаляє PostgreSQL і серверні дані.

На ПК з уже наявною установкою в іншій папці **оновіть саме ту папку**:
збережіть .env.nodocker та .local, розпакуйте QureMed-Local-Server у неї,
зупиніть сервер, запустіть Update-QureMed.cmd від адміністратора, потім Start.
Не створюйте другу установку сервера з іншими налаштуваннями тієї самої БД.
Клієнт можна встановити EXE-інсталятором у режимі «Робоче місце».

## Android і сертифікат

У програмі вводиться **адреса ПК-сервера**, для поточного центру
https://192.168.1.106. IP телефона та шлюз/DNS роутера 192.168.1.1 для цього
не використовуються. На іншому ПК-сервері буде його власна адреса.
Закріпіть адресу ПК у DHCP роутера, щоб вона не змінювалася.

1. На сервері після запуску знайдіть QureMed-Local-CA.crt поруч із Start-QureMed.
2. Передайте лише цей публічний файл на телефон, наприклад USB-кабелем.
3. Android → Безпека → Інші налаштування безпеки → Установити сертифікат →
   **Сертифікат CA**. Виберіть файл. Назви меню залежать від телефона.
4. Перевірте дату/час, підключіть телефон до Wi-Fi центру та натисніть
   «Оновити» в RehaFlow. Застосунок також має кнопку з цією інструкцією.

Сертифікат має походити саме від цього сервера. Після перевстановлення CA
довіру на пристроях потрібно налаштувати заново. Помилки TLS не ігноруються.

## Інтерфейс і права

Windows відкривається розгорнутим. Адреса зникає після завантаження React,
повторне підключення використовує збережену адресу. Змінити її можна з
налаштувань або з екрана входу. При помилці підключення поле знову доступне.
Ефекти «Авто/Повні/Еко» розміщено в налаштуваннях. Нижні службові підписи прибрано.

Реєстратура бачить пацієнтів, архів, огляд, вільні місця та розклад; реєструє,
розміщує й записує пацієнтів. Створення палат/ліжок/кабінетів доступне лише
адміністратору. Призначення та медичні огляди реєстратурі недоступні.
Повідомлення надсилає лише адміністратор; адресати читають і підтверджують їх.
Права перевіряються API, включно з уже створеними обліковими записами.

При закритті Windows: «Так» завершує активну робочу зміну і поточну сесію,
«Ні» закриває клієнт без завершення зміни, «Скасувати» залишає вікно відкритим.
Незавершені взяті завдання блокують завершення зміни до повернення/передачі/
виконання. Помилка зв’язку не видається за успішне завершення.
15-денна передача пацієнтів лікарем залишається окремою дією.

Технічні джерела: [закриття WinUI-вікна](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.windowing.appwindow.closing?view=windows-app-sdk-1.8),
[компоненти Inno Setup](https://jrsoftware.org/ishelp/topic_componentssection.htm),
[довіра до користувацьких CA в Android](https://developer.android.com/privacy-and-security/security-config).
