# RehaFlow: команда центру, локальна БД і Android

## Де працює програма

- PostgreSQL та Node.js API працюють на комп’ютері центру. DATABASE_URL використовує
  127.0.0.1; телефони не підключаються безпосередньо до PostgreSQL.
- Windows залишається WinUI 3 + WebView2. React — інтерфейс усередині цього вікна.
- Android APK — окремий Android-застосунок із системним WebView, екраном адреси
  сервера, вибором/збереженням документів і друком. Він відкриває той самий React.
- Початкова адреса клієнтів: https://192.168.1.106. Це має бути адреса ПК із сервером,
  а не шлюзу роутера. Адресу можна змінити. Налаштування установки перевіряє,
  що обраний IP належить цьому ПК. Зарезервуйте IP ПК у DHCP роутера.
- Зовнішній інтернет потрібний для першого встановлення залежностей/збірки.
  Для щоденної роботи достатньо мережі центру і ввімкненого ПК-сервера.

## Перше встановлення без Docker Desktop

1. Завантажте вихідний код цієї гілки на комп’ютер центру.
2. Запустіть `Start-QureMed-Without-Docker.cmd` від адміністратора.
3. Інсталятор встановлює Node.js/PostgreSQL за потреби, створює локальну БД,
   запитує пароль адміністратора, збирає API/React та налаштовує Caddy HTTPS.
4. Не закривайте вікно сервера під час роботи. PostgreSQL зберігає дані у своєму
   каталозі даних Windows; `.env.nodocker` містить параметри доступу.
5. Після запуску поряд із програмою з’явиться **QureMed-Local-CA.crt**. Це публічний
   сертифікат для довіри до HTTPS вашого центру. Приватні ключі у `.local` не передавайте.
6. На Android підключіться до Wi-Fi центру, встановіть CA-сертифікат у системних
   налаштуваннях безпеки (назва меню залежить від виробника). Установіть APK,
   введіть адресу сервера й увійдіть особистим логіном.
7. Якщо Windows-клієнт запущений на іншому ПК, також установіть CA центру через
   `scripts/Trust-Local-Certificate.ps1` згідно з README.

Порт 443 відкривається лише для приватної мережі й локальної підмережі; Node.js
слухає 127.0.0.1:3000. Немає потреби відкривати порт БД на роутері чи налаштовувати
переадресацію з інтернету. Якщо 192.168.1.106 не належить ПК, подивіться IPv4 через
`ipconfig`, а потім запустіть `scripts/Enable-LanHttps.ps1 -ServerIp <IPv4-ПК>`.

## Оновлення наявної установки

Зупиніть RehaFlow-сервер, розпакуйте нові вихідні файли в папку установки,
зберігаючи `.env.nodocker` і `.local`. Запустіть **Update-QureMed.cmd** від
адміністратора. Він створює резервну копію PostgreSQL, збирає програму та
узгоджує HTTPS. Потім запустіть Start-QureMed-Without-Docker.cmd. Міграція 002
виконується транзакційно при старті, додаючи таблиці/поля без видалення карток.
Для нової теми необхідно оновити серверний React; лише заміни EXE недостатньо.

Резервні копії: `scripts/Backup-NoDocker.ps1`, за замовчуванням `.backups`.
Документи зберігаються в БД і включені в pg_dump. Для відновлення спершу перевірте
dump у **новій порожній тестовій БД** через `pg_restore --no-owner --no-acl -d <test-db> <file.dump>`.
Перемикати робочу БД слід лише після перевірки відновлених даних; поточну БД не видаляйте.

## Робочі процеси

| Роль | Доступні нові можливості |
|---|---|
| Реєстратура | Адреса, контакт близької людини, направлення, стаціонар/амбулаторно, дублікати, повторне надходження, документи, друк картки, поверх/палата/ліжко, розклад спеціаліста |
| Лікар | Усі активні пацієнти й фільтр «мої», лікуючий лікар у картці, 15-денний термін, передача обраних пацієнтів, огляди/алергії/діагноз/план, курси призначень, виписний підсумок, повідомлення |
| Медсестра | Зміна, пошук за пацієнтом/палатою/поверхом, призначення за часом, підтвердження особи, виконано/не виконано з причиною, вимірювання, передача зміни, повідомлення |
| Реабілітолог | Окрема роль, пул своїх процедур, розклад спеціаліста, цілі, оцінювання, результати й наступний план, передача робочої зміни |

Передача лікаря: поточний лікар обирає пацієнтів, наступного лікаря та пише підсумок.
До прийняття відповідальний не змінюється. Лише зазначений лікар може прийняти
передачу; після прийняття починається новий період 15 днів. Історія попереднього
лікаря та його призначення залишаються. Повторне прийняття відхиляється.
Після 15 днів з’являється нагадування; автоматичної зміни лікаря немає.

Передача медсестри/реабілітолога: колега починає свою зміну та приймає підсумок.
Незавершені завдання знімка передачі переходять до колеги; закриті завдання не
відкриваються знову. Попередня зміна закривається, якщо її виконавцю не залишилося
завдань. Якщо він узяв нові завдання після передачі, їх треба завершити окремо.

Призначення ліків вимагає препарату, дози, одиниць і шляху введення. Курс створює
окреме завдання на кожен час, до 90 виконань. Інтервал задається у годинах.
Виконання вимагає підтвердження ПІБ/дати народження; фактичний час фіксує сервер.
«Не виконано» зберігається окремою ознакою і не входить у лічильник успішних виконань.
Призначення саме по собі не резервує кабінет: для цього є розклад із перевіркою
перетинів пацієнта, кабінету та спеціаліста.

Записи не перезаписуються. Автор додає виправлення із посиланням на оригінал.
Реєстраційні зміни зберігають попередні значення; API події записуються в аудит.
Документи: PDF/JPEG/PNG до 5 МБ. Друкується відкрита вкладка картки.

## APK та перевірки

GitHub Actions → **RehaFlow Android APK** → успішний запуск → артефакт
**RehaFlow-Android-test-APK** → розпакуйте `app-debug.apk` і встановіть на Android 8+.
Це підписаний тестовим ключем APK із applicationId `com.quremed.rehaflow.test`.
Ключ CI може відрізнятися між збірками: якщо оновлення не встановлюється, попередній
тестовий APK доведеться видалити (дані пацієнтів на сервері збережуться, адресу й
вхід на телефоні налаштуйте знову). Для стабільного розповсюдження потрібен окремий
постійний ключ релізного підпису, його не включено в репозиторій.

Збірка сервера/React: `npm ci`, `npm run build`. Тести: `npm test` (PGlite локально,
PostgreSQL у CI, окрема схема тестів Care). Windows workflow додатково перевіряє
синтаксис PowerShell і запуск React у WinUI/WebView2. Android workflow збирає APK
і запускає lint, але не замінює перевірку на реальному телефоні.

Повідомлення та оновлення працюють у відкритому застосунку (до 15 секунд).
Фонових Android push-сповіщень із закритим застосунком у цій версії немає.
Офлайн-записи не ставляться у приховану чергу: при втраті зв’язку відображається
непідтверджений стан. Перед повтором операції після тайм-ауту перевірте, чи сервер
її вже зберіг. «Авто/Еко» керує легкими ефектами без зміни клінічних функцій.

Версії Android-інструментів звірено з [офіційною сумісністю AGP 8.7](https://developer.android.com/build/releases/agp-8-7-0-release-notes).
Локальна довіра до CA використовує [Android Network Security Configuration](https://developer.android.com/privacy-and-security/security-config), без обходу помилок TLS.
