# RehaFlow 2.3 — щоденна робота центру

Код доповнює 2.2. Нові APK/EXE ще не зібрані через недоступність GitHub Actions. Сервер і React збираються локально; Windows-планувальник та відновлення на реальному ПК потребують перевірки.

## Що працює в коді

- Огляд за роллю: вільні ліжка, надходження/виписки, власні пацієнти лікаря, прострочені й узяті завдання, записи на сьогодні. Показники обмежені правами.
- Адміністратор бачить активні зміни, останню успішну копію й перевірку відновлення. Понад 36 годин без копії — попередження.
- Медсестра/реабілітолог окремо підтверджує отримання завдання. Це не бере його у роботу; взяття й виконання залишаються окремими діями. Лікар бачить кількість підтверджень. Повторне підтвердження тією ж людиною не дублюється.
- Завдання: Зараз (до наступних 30 хвилин включно з простроченими), Далі, Прострочені. Перед передачею зміни показано незавершене; прийняття передає лише актуальні завдання.
- Стрічка пацієнта об'єднує надходження, виписку, медичні записи, передачі, призначення та останні відомі взяття/виконання. Історію всіх повторних взяттів дивіться в журналі аудиту. Реєстратор не отримує клінічні завдання стрічки.
- Статус збереження відокремлено від оновлення. Невизначений результат запису не приховується фоновим GET. Перевірте фактичний стан, тоді натисніть «Стан дії перевірено»; автоматичних повторів медичних записів немає.
- API має номер сумісності 1. Сервер відхиляє явно несумісний номер; версія продукту 2.3 повертається health endpoint.
- Резервування перед оновленням залишається обов'язковим. Нові .dump спочатку записуються як .partial, перевіряється структура архіву, потім фіксуються дата, розмір і SHA-256. Це не замінює повного тестового відновлення.

## Увімкнення на наявному сервері

1. Збережіть робочу копію БД. Оновлюйте початкову папку сервера; збережіть .env.nodocker та .local з сертифікатами.
2. Зупиніть поточний сервер перед Update-QureMed.cmd. Не запускайте другий Caddy. Оновлення виконуйте від адміністратора, як раніше.
3. Запустіть Enable-Maintenance.cmd під тим Windows-користувачем, який налаштував сервер. Завдання користувацькі, пароль Windows не зберігається.
4. Сервер запускатиметься приховано після входу цього користувача у Windows. Це НЕ служба до входу в систему. Не виходьте з облікового запису під час роботи центру; блокувати екран можна.
5. Копія щодня о 12:00, пропущений запуск — за доступності користувацького сеансу. У планувальнику перевірте завдання RehaFlow Server та RehaFlow Backup. Поточний ручний сервер під час встановлення завдань не зупиняється й другий не запускається.
6. Запустіть RehaFlow Backup вручну в планувальнику й перевірте результат в огляді адміністратора.
7. Копії не видаляються автоматично. Контролюйте вільне місце, переносьте перевірені копії на окремий захищений носій. Копія на тому ж диску не захищає від його поломки.
8. Для вимкнення завдань: powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Install-Maintenance.ps1 -Remove.

## Перевірка відновлення

У PowerShell із папки сервера:
```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Test-Backup-NoDocker.ps1 -BackupFile "C:\path\quremed-backup.dump"
```

Введіть на ПК наявний пароль PostgreSQL postgres. Не надсилайте його в чат.
Скрипт створює окрему БД rehaflow_verify_<випадковий ідентифікатор>, відновлює архів, читає таблиці пацієнтів, завдань і документів, після чого видаляє лише цю тестову БД.
Робоча БД не перезаписується. Якщо видалення тестової БД не вдалося, скрипт повідомить її назву.
Відновлення потребує додаткового місця для повної копії БД. Використовуйте лише власні довірені резервні архіви.
Успішний тест записує дату й хеш перевіреного архіву для огляду адміністратора.

## Перевірка на пристроях після збирання

Реєстратор реєструє тестового пацієнта → лікар створює завдання → медсестра підтверджує отримання → бере в роботу → підтверджує особу й виконує → лікар бачить результат і стрічку.
Окремо перевірте передачу незавершених завдань та розрив Wi-Fi під час збереження.
Звук, фонові обмеження Android і CA-сертифікат описані в STAFF-2.2.md.
Тести на реальному телефоні, Windows-планувальнику та відновленні БД тут не виконані.
