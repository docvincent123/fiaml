# RehaFlow — QureMed Industries

Медична ERP для локальної мережі реабілітаційного центру: NestJS + PostgreSQL, React для телефонів/планшетів і нативний WinUI 3 для Windows. Усі клієнти використовують один API та спільну базу.

## Що реалізовано

- Особистий вхід, паролі зі scrypt, обмеження спроб входу; JWT і серверний реєстр сесій.
- Ролі ADMIN / REGISTRAR / DOCTOR / NURSE, вимкнення окремих прав у межах ролі, динамічне меню і серверна перевірка кожної операції.
- Керування працівниками, спеціальність лікаря, деактивація облікового запису; зміна прав відкликає сесії.
- Онлайн-сесії: пристрій, IP, користувач, остання активність, завершення сесії адміністратором. «Онлайн» означає heartbeat за останні 90 секунд.
- Пацієнти: реєстрація, пошук, редагування контактів, лікар, розміщення; медичні записи з автором та часом.
- Палати, ліжка, унікальне зайняття, QR-коди; QR відкриває поточного пацієнта після авторизації. Камера телефону може сканувати код без окремого застосунку.
- Виписка в архів, збереження історії госпіталізацій і записів, повторна госпіталізація.
- Кабінети та записи: заборона одночасного зайняття кабінету/пацієнта, скасування і завершення записів.
- Призначення: створення лікарем, час, тип, кабінет; атомарне взяття медсестрою, завершення тільки власником, повернення в пул, скасування автором.
- Зміна медсестри до 12 годин; завершення лише після виконання/повернення взятих завдань.
- Socket.io invalidation після commit через transactional outbox; веб також синхронізується раз на 15 секунд. Десктоп оновлює завдання і сесії раз на 30 секунд.
- Журнал дій, читання карток, скрипти резервного копіювання/відновлення.
- Футер усіх клієнтів: **сервери QureMed Industries**.

## Швидкий запуск на Windows

### Комп’ютер-сервер

1. Встановіть Docker Desktop з Linux containers і запустіть його. Підготовка вперше потребує інтернету; після завантаження образів щоденна робота центру локальна.
2. Завантажте цей репозиторій через **Code → Download ZIP**, розпакуйте.
3. Закріпіть локальну IPv4-адресу комп’ютера в роутері (DHCP reservation), наприклад `192.168.1.100`.
4. Запустіть **Start-QureMed.cmd**. Вкажіть IP сервера та власний початковий пароль адміністратора (12+ символів).
5. Дочекайтеся завершення запуску. Скрипт створить локальні секрети, PostgreSQL, сервер і HTTPS proxy. Пароль не показується у консолі. Дані БД зберігаються у Docker volume.
6. Запустіть `scripts/Trust-Local-Certificate.ps1` на Windows-клієнті, де лежить `QureMed-Local-CA.crt`, щоб довірити локальний HTTPS. Сертифікат містить лише публічний CA; приватні ключі залишаються на сервері.
7. Відкрийте `https://ВАШ-IP`. Логін **admin**, пароль — той, який ви ввели. Створіть команду, палати, ліжка, кабінети та пацієнтів.

Важливо: порт 443 повинен бути доступний у приватній мережі Windows Firewall. PostgreSQL назовні не публікується. Сервіс не потрібно відкривати в інтернет через роутер.

### Телефони

1. Підключіть телефон до тієї самої мережі, що й сервер.
2. Передайте **лише публічний** `QureMed-Local-CA.crt` на телефон. Для iPhone встановіть профіль сертифіката та увімкніть довіру до цього кореневого сертифіката в налаштуваннях довіри сертифікатів. На Android встановіть CA для браузера згідно з політикою пристрою.
3. Відкрийте `https://ВАШ-IP` у браузері, увійдіть під власним обліковим записом. За бажанням додайте посилання на головний екран.
4. Медсестра відкриває **Моя зміна → Почати зміну**; лікар — **Пацієнти / Призначення**.

Телефонна версія — адаптивний вебклієнт. Це не окремі IPA/APK і не офлайн-копія медичних даних. Без доступу до сервера зміни не записуються.

### Десктоп

У **Actions → QureMed build and tests → успішний запуск → Artifacts** завантажте **RehaFlow-Windows-x64**. Розпакуйте **всю папку**, запустіть **RehaFlow.exe**. Вкажіть адресу `https://ВАШ-IP`, логін і пароль. Для цього користувача Windows має бути довірений локальний CA.

Додаток нативний WinUI 3, без Electron чи WebView. Поширюється папкою з runtime, а не одним самодостатнім файлом. Підтримка: Windows 10 1809+ / Windows 11 x64; рекомендовано актуальну підтримувану Windows. Публікація артефакта залежить від успішної Windows-збірки та доступної квоти GitHub Actions.

## Щоденна робота

- `Start-QureMed.cmd` запускає/оновлює сервіси, не скидаючи дані. Потрібен запущений Docker Desktop.
- `scripts/Stop-Local.ps1` зупиняє сервіси, зберігаючи БД.
- `scripts/Backup.ps1` створює dump в `backups/`; регулярно копіюйте його у захищене зовнішнє сховище.
- `scripts/Restore.ps1 -BackupFile C:\path\quremed.dump` замінює БД після введення RESTORE; перед операцією створіть резервну копію поточних даних. Після відновлення всі старі сесії відкликаються.
- Не запускайте `docker compose down -v`: це видаляє томи з даними та сертифікатами.
- Не передавайте `.env` працівникам і не завантажуйте його в GitHub.
- Початковий ADMIN_PASSWORD використовується лише коли таблиця users порожня. Подальша зміна — у налаштуваннях програми.

## Архітектура та обмеження

```text
server/   NestJS API, PostgreSQL repositories, auth, sessions, audit, outbox
web/      React + Tailwind, телефон / планшет / браузер ПК
desktop/  WinUI 3, нативні екрани і форми
scripts/  локальний запуск, сертифікат, backup / restore
```

Схема: `server/sql/001_initial.sql`. Пацієнт та його госпіталізації — окремі сутності. На одну активну госпіталізацію дозволене одне ліжко. Унікальні часткові індекси захищають зайняття ліжок. Статус зайнятості обчислюється за активною госпіталізацією.

Конкурентне взяття — `UPDATE ... WHERE status='OPEN' AND taken_by IS NULL RETURNING *`, а не попередній SELECT стану із незахищеним записом. Другий запит отримує 409. Patient row lock синхронізує взяття/створення/виписку. Записи до кабінету серіалізуються блокуванням рядків пацієнта та кабінету; SQL репозиторій — єдиний автор записів, клієнти не мають доступу до БД.

Веб і WinUI ніколи не є джерелом прав. API кожного запиту звіряє сесію, активність користувача та актуальні права в БД. Індивідуальні права можна звужувати в межах фіксованих ролей. Надавати медсестрі адміністративні можливості заборонено. Користувацькі нові ролі поки не підтримуються.

Події realtime містять лише сигнал зміни, без даних пацієнтів. Клієнти перезапитують API. Поточна конфігурація — один API instance, один центр, один ресурс на кабінет. Для групових занять потрібна модель місткості; для кількох API instances — Socket.io backplane. Записи/пацієнти/задачі обмежені 500 рядками у відповіді, audit/sessions — 300; для масштабування потрібна cursor pagination.

Немає бухгалтерії, складу медикаментів, лабораторних інтеграцій, електронного підпису, вкладень, телемедицини чи push-сповіщень при закритому браузері. Це реалізація погоджених клінічних модулів, а не всіх можливих ERP-функцій. Автоматизація backup за розкладом налаштовується адміністратором ОС. Оновлення `.env` і довіра до HTTPS — одноразові кроки локального розгортання.

## Розробка та перевірка

Node.js 22+, PostgreSQL 17. `npm ci`, `npm run build`, `npm test`.

Тести за замовчуванням використовують PostgreSQL WASM (PGlite) для ізольованих сценаріїв. `TEST_DATABASE_URL` перемикає їх на справжній PostgreSQL у **порожній одноразовій тестовій БД**. GitHub Actions перевіряє конкурентні запити саме на PostgreSQL 17. Не вказуйте бойову БД у тестах.

Для запуску без Docker задайте environment: `DATABASE_URL`, `JWT_SECRET` (32+ символів), `ADMIN_PASSWORD` (12+), `PUBLIC_URL=http://localhost:3000`; `npm start`. Сервер автоматично застосовує початкову міграцію. Для локального development без TLS не задавайте NODE_ENV=production. Для LAN використовуйте HTTPS через комплектний Caddy.

Windows build: `dotnet publish desktop/QureMed.Desktop/QureMed.Desktop.csproj -c Release -r win-x64 -p:Platform=x64 --self-contained true -o artifacts/desktop` на Windows з .NET 8 SDK.

Перед використанням з реальними медичними даними перевірте конкретне розгортання: права кожної ролі, HTTPS на пристроях, backup і тестове відновлення. Автоматичні тести не замінюють приймання працівниками центру.
